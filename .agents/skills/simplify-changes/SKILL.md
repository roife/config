# Simplify Changes

减少理解和维护代码所需的概念、跳转与重复，保留有价值的抽象。

## 范围

从请求和上下文确定文件、模块或 diff。“化简你的修改”限于当前任务的变更，区分同文件内其他人的修改；空 diff 不意味着改扫全仓。只有范围存在实质歧义且无法从上下文判断时才澄清。

按请求区分建议与修改；已有执行授权就直接完成，不在分析后再次询问是否实施。为理解行为按需读取调用者，不扩展为无关重构。

## 化简判断

- 优先复用标准库和项目已有工具，核对替换是否改变顺序、异常或边界行为。
- 删除纯转发 wrapper、无价值的参数传递和回调绕行，合并真正重复的解析、状态与分支；保留表达领域含义或所有权的抽象。
- 删除兼容分支前核对支持范围；没有本地调用者不能证明公开 API 或动态入口无人使用。
- 根据类型、调用契约或实际实现判断防御逻辑是否冗余。保留外部输入、I/O、取消和资源释放所需的处理；不靠吞异常或删失败测试制造通过。

发现行为缺陷时，按已有修复授权处理，不能把行为改变称作等价化简。没有有依据的改进时可以零修改结束。

## 验证与交付

按实际风险选择现有测试、编译或复现路径；简单内联不需要新增镜像测试，也不固定重跑全量检查。完成后检查最终 diff 是否仅包含预期变化，简要报告实质简化和验证结果，说明影响结论的未验证项。
