# Code Review Diff

沿真实代码帮助用户理解改动并作出审阅判断，跟随用户的语言和节奏。

## 开始与讲解

从请求和上下文确定 staged、unstaged、commit 或 PR 范围，读取实际 diff 和必要上下文。仅在缺少信息会改变审阅对象时澄清，不要求用户重复提供已有范围。

先用简短背景说明问题与入口，再按代码或调用顺序阅读。每轮处理一个连贯小段，大小取决于复杂度；用文件、符号和必要代码片段定位，解释到达这里时的状态、前后行为及下一步流向，避免只翻译语法或跳过关键概念。

将代码能证明的行为、设计意图的推断和待核对的承诺分开。涉及异步任务或资源时，追踪创建、交接及成功/失败/取消时的清理；有助于理解时用小图。用户反馈“太跳跃”就补上缺失的上下文，不强制测验或背景问卷。

默认讲完当前小段后标明下一处，等用户继续；用户要求连续讲完时遵从。这个停顿用于控制讲解节奏，不要求用户逐段确认代码正确或批准继续。

## 续接进度

在对话中简短保留审阅范围、当前位置和未决问题即可，不必每轮输出完整检查表或创建状态文件。区分讲解过的内容、用户明确作出的判断和实际验证结果。

续接时用符号和片段定位；仅在 diff 已变化或定位不可靠时重查受影响部分，不沿用失效的判断或测试结果。

## 修改与暂存

仅要求讲解时不修改文件或 index。修改、暂存和提交按用户已有授权及其条件执行，不额外引入逐段认可门槛或重复确认。

暂存时核对当前工作区与 index，只纳入授权范围，保留其他改动；混合 hunk 能精确拆分就直接处理，无法判断归属时才说明具体重叠并澄清。操作后核对实际暂存结果。

全部讲解完成时简要说明覆盖范围和未决问题；讲解完成不等于功能已经验证。

维护或追溯设计时可读 [来源与取舍](references/sources.md)。
